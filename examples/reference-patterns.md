## Acquire a feature, preserve its connections

1. Start with the relevant section below. Read the linked `item.json` and its catalogue entry under `index/`; the GUID in its path is the portable definition identity. Custom Code such as `vdmUploaderConfig` uses a natural key instead. Local database row numbers are not portable identities.
2. Use the [repository network](../standards/repository-network.md) to locate the current logical source, then the [package acquisition workflow](../packages/workflows/validate-and-integrate.md#2-configure-acquisition-and-external-sources) to acquire the selected Field, Admin View or component. Acquiring a Field alone does not attach it to a new parent or provide every reverse reference. Inspect parent-owned records such as `src/admin_view/children/<parent-guid>/admin-fields.json` and component view attachments as well.
3. Follow the feature's whole dependency graph: fields and nested fields, persisted Admin Views, Custom Code, Dynamic Gets, templates/layouts, libraries/assets, Field Types, Joomla Powers and Super Powers. Preserve dependency-discovery references in authored code, including intentional layout-reference comments. Configure external catalogues separately. When package records span repositories, follow the acquisition workflow's selected-repository rules; do not assume Pull searches every repository automatically.
4. Apply [entity reuse and identity adaptation](../standards/entity-reuse.md). Unchanged reuse retains its identity; an independent adaptation gets the model-appropriate new identity with coherent remapping. Adapt domain names, target tables, aliases, permissions and data fields together. Keep placeholders and upstream licensing. Importing a whole reference component is useful for exploration; the deliverable should contain the features the requested application needs.
5. Compile and install the consuming extension, then exercise the feature through its real GUI and site output. Use [a comment probe and compiler diagnostics](../packages/workflows/debug.md#trace-a-gui-code-field) to map unfamiliar authoring fields to generated files. Return lasting changes to the blueprint and regenerate.

# Return to the originating Admin View

Use this workflow when an administrator should open a related record in a normal Joomla editor and return to the exact originating page on **Save & Close** or **Close/Cancel**. Use [modal relationships](modal-relationships.md) instead when the task is to select a record and update the still-open form. A return route neither writes a relationship nor preserves unsaved input.

**Scope and authority:** standard generated Admin View forms and controllers, not an arbitrary custom controller, modal, or frontend route. Use the project's [current JCB version policy](../../standards/version-policy.md). Source reviewed 27 November 2026: the shipping JCB example at `v6.2.1`, commit `beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd`; the Joomla 6 generation path at `6.x@037752c7e6599aa4cec900138dfb61af7ee4ba8f`. Inspect the actual target compiler and emitted extension; the two baselines are not interchangeable.

## The working JCB reference

1. In JCB open **Admin Views → Look (demo-J6) → Fields → Linked Fields Edit**. The pencil beside **More Details** opens the Field definition. In the inspected prepared Playground these are Admin View ID `325` and Field ID `3415`; find the records by label on other databases. JCB warns before leaving because the originating form's unsaved work is not carried.
2. The [Admin View script](https://github.com/joomengine/Joomla-Component-Builder/blob/beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd/media/js/admin_view.js#L642-L644) requests the linked fields. [AjaxModel::getViewID](https://github.com/joomengine/Joomla-Component-Builder/blob/beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd/admin/src/Model/AjaxModel.php#L2768-L2818) resolves the existing view context from the session. [getAjaxDisplay and processItemName](https://github.com/joomengine/Joomla-Component-Builder/blob/beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd/admin/src/Model/AjaxModel.php#L3219-L3424) build the origin route and use the edit helpers to render the link, resolving GUID-backed relations to the editor's numeric ID when required.
3. The pencil first runs Joomla's normal `view=fields&task=field.edit&id=3415` entry route with the referral query. The resulting edit URL is:

   ```text
   /administrator/index.php?option=com_componentbuilder&view=field&ref=admin_view&refid=325&layout=edit&id=3415&return=aW5kZXgucGhwP29wdGlvbj1jb21fY29tcG9uZW50YnVpbGRlciZ2aWV3PWFkbWluX3ZpZXcmbGF5b3V0PWVkaXQmaWQ9MzI1
   ```

   The decoded value is `index.php?option=com_componentbuilder&view=admin_view&layout=edit&id=325`. It names the **origin**, not the Field being edited. [The native edit helpers](https://github.com/joomengine/Joomla-Component-Builder/blob/beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd/admin/src/Helper/ComponentbuilderHelper.php#L4166-L4312) use Joomla's edit task, access and checkout rules rather than treating a rendered pencil as authorization.
4. The receiving [Field HtmlView](https://github.com/joomengine/Joomla-Component-Builder/blob/beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd/admin/src/View/Field/HtmlView.php#L241-L303) carries the context in its [form action](https://github.com/joomengine/Joomla-Component-Builder/blob/beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd/admin/tmpl/field/default.php#L60). The [Field controller](https://github.com/joomengine/Joomla-Component-Builder/blob/beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd/admin/src/Controller/FieldController.php#L442-L601) defers normal cancel/save work to Joomla, then prefers a decoded internal `return`, falls back to the referring edit screen when both `ref` and `refid` exist, or to the referring view for `ref` alone. Without referral context it leaves the ordinary Joomla flow in place, with separate modal behavior where applicable. A referred save uses the closing save task so normal check-in can take place.

## Build the same pattern inside your component

1. **Identify the real records and routes.** Attach both database-backed Admin Views to the component in JCB; use its normal [Admin View authoring](../models/admin-views.md). Record the component option, the origin's singular code, the destination's singular and list codes, and the relationship used to resolve the destination. Build from a saved origin. For example, an Order edit form can open its linked Customer. Resolve the relationship through the model if it stores a GUID; pass the Customer's actual numeric Joomla editor ID to the task. Do not hard-code either record ID or substitute the parent ID for the target ID.
2. **Author the launcher at the source, not in generated files.** For an inline link on the origin's Admin View, one native insertion point is the owning [Admin Custom Tabs](../reference/admin_custom_tabs.md) record's `tabs[].html` field. Put only presentation there; have the origin model or its Power resolve the persisted destination when a lookup is needed. Render only when the actor can use the destination and the record is available; use the actual component's access/edit and checkout rules. For an existing toolbar action, use [Admin View Custom Buttons and PHP Controller](admin-authoring-patterns.md#3-a-native-administrator-action-with-controller-and-model) and let that origin action route to the same destination after its normal checks. Neither path needs custom save/cancel methods on the target.
3. **Build and route the link.** The example below is the route-building part, after the origin has a positive `$orderId` and the related Customer has been resolved as an editable `$customerId`. Substitute the actual component and view codes. A task URL starts in the destination list view with the singular `customer.edit` task; use the editor URL only to check the resulting navigation.

   ```php
   $origin = 'index.php?option=com_orders&view=order&layout=edit&id=' . (int) $orderId;
   $target = 'index.php?option=com_orders&view=customers&task=customer.edit&id=' . (int) $customerId;
   $target .= '&return=' . rawurlencode(base64_encode($origin));
   $url = Joomla___d4c76099_4c32_408a_8701_d0a724484dfd___Power::_($target, false);
   ```

   In HTML, escape the routed URL for the quoted attribute exactly once using the appropriate view/output helper. Use a translated label and, when leaving a form that can have unsaved changes, the existing confirmation pattern or require the user to save first. Do not use history, the browser Referer header, or a tab button as a substitute for the explicit route. Do not put secrets or unsaved values in the URL.
4. **Leave the receiver generated.** Compile for your target and inspect the emitted administrator singular controller, `HtmlView`, and `tmpl/<view>/edit.php` or the actual edit template used by that release. The normal edit task must preserve the return into the editor; the generated view/form must carry it into Save & Close and Close/Cancel. On the inspected Joomla 6 generation path, see [ADMIN_VIEW_HTML::setReturn](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/admin/compiler/joomla_6/ADMIN_VIEW_HTML.php#L223-L245), [the form template](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/admin/compiler/joomla_6/ADMIN_VIEW.php#L27), and [the generated controller template](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/admin/compiler/joomla_6/ADMIN_VIEW_CONTROLLER.php#L110-L273). Fix missing wiring in the JCB-owned authoring record, not the compiled installer or running files.

## Create, nested returns and compatibility

- **Create:** use the destination's normal `customer.add` task if it is available for your generated view and only when the actor can create. Do not send a positive target ID. The JCB application's own [create launcher](https://github.com/joomengine/Joomla-Component-Builder/blob/beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd/admin/src/Model/AjaxModel.php#L2830-L2874) instead opens a new edit layout, includes `return`, and can separately supply `init_defaults` as URL-encoded JSON. Only use that parameter for defaults the receiving model actually accepts. Prefilling a relationship is not authorization: validate the submitted relationship through the normal model before saving.
- **Nested navigation:** if Order opened Customer with a valid return and Customer opens another editor, include Customer's existing `return` as a query parameter of the Customer **origin route** before encoding that entire route for the next editor. Do not forward the original token as the next editor's return unchanged: that would skip Customer. Use only an expected, validated internal route and let each query boundary encode its own value once.
- **Compatibility:** use `return` for new navigation. Keep `ref` and `refid` only when a traced existing receiver needs them. The inspected Field view labels them legacy; [older new-record defaults](https://github.com/joomengine/Joomla-Component-Builder/blob/beb33d8c7d5749ebb9e6b912aaeb9460caf9e4fd/admin/src/Model/FieldModel.php#L654-L682) may also consume them, so do not strip them from an existing flow without checking the model. If carrying nontrivial or nested values, verify reserved characters survive the form action and redirects in the target release.
- **Boundary:** Base64 is reversible transport, not validation, authentication or encryption. Construct a known internal route and keep the generated controller's internal-URL check, ACL, form token and checkout behavior. Use the normal standalone destination when return context is absent or rejected. Do not apply this admin recipe unchanged to custom forms or Site Views; check the actual receiver first.

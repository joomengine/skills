# Reuse the immediate language translation importer

To translate a component rather than adapt the importer itself, start with the full [language-string workflow](language-strings.md): authoring, collection, published languages, filters/export, workbook translation, import mapping and compiled/installed verification.

Use JCB's language translation importer as the native reference for a **download example → upload → map → Apply** workflow. It imports spreadsheet data into JCB's `language_translation` records; it is neither Joomla INI installation nor the Demo queue processor. For another application, adapt the complete composition through [immediate import](immediate-import.md), using that application's tables and rules.

**Source authority:** [core Joomla Component Builder](https://github.com/joomengine/Joomla-Component-Builder/tree/037752c7e6599aa4cec900138dfb61af7ee4ba8f), `6.x@037752c7e6599aa4cec900138dfb61af7ee4ba8f`, is the final source of truth for this feature and its compiler mapping. The visible composition, native insertion points and Ajax dispatch were rechecked there on 2026-11-11; the service trace below was inspected at the same revision on 2026-11-09. Apply the [latest JCB version policy](../../standards/version-policy.md); this hash identifies inspected evidence, not a required runtime version.

## Author the native JCB graph

This is a **source-verified native reconstruction route**. The source identifies what to author and how the compiler consumes it; proceed to build and validate that graph. The remaining limit is verification: this documentation task did not recover an original authoring export or compile a new reconstruction. The [evidence receipt](../evidence/importer-building-blocks.md) keeps those statuses separate from the existing importer's runtime evidence. Use the [native concept map](../../architecture/concepts.md) if the view/query distinction is unfamiliar.

Start from the [Model](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/admin/src/Model/Import_translationsModel.php#L221-L291) and [View](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/admin/src/View/Import_translations/HtmlView.php). Create the smallest complete graph in this order:

| Native record or field | What to author and preserve |
| --- | --- |
| Dynamic Get | `gettype=1` (Item), `main_source=3` (Custom). Put the session/file-type initialization from `getItem()` into `php_custom_get`, ending with `$data = (object) ['guid' => $guid, 'file_type' => $file_type]`. Adapt session prefixes, formats and temporary-path settings. Do not paste the generated ItemModel class or `getItem()` wrapper. |
| Custom Admin View | Set a coherent codename, name and `main_get` pointing to that getter. Attach it through the component's Custom Admin Views association. The `default` body loads the uploader Template; the generated output must retain one `adminForm`, task field, CSRF token and toolbar submit handling. |
| Model/controller hooks | Enable `add_custom_button=1`. Put `getTmpPath()` in `php_model`; put Example, Apply, return/back, payload conversion and cleanup methods in `php_controller`. Define Example/back custom buttons; Apply is invoked from the mapping Layout. Keep permissions, CSRF, owned-file lookup and result handling with these actions. |
| Uploader Template | Alias `translationimporterareajsix`, or a coherent application alias. Put setup PHP in enabled `php_view` and markup/events in `template`. Preserve `$this->item->guid` and `$this->item->file_type`, progress/error/display areas and restoration of the uploader after deletion. |
| Mapping/help Layouts | Aliases `translationimportercolumnsdisplayjsix` and `translationimportereasymappingjsix`, or coherently adapted aliases. Use enabled `php_view` for setup and `layout` for presentation. Build the inline mapping controls under `vdm_import`, using the same header/target definition as Example. |
| Ajax hooks | Enable `add_php_ajax=1`, provide the four methods in `php_ajaxmethod`, and configure their `ajax_input` arguments/filters below. JCB generates the shared Ajax model/dispatch; a new hand-written Ajax controller is unnecessary. |
| Document/assets hook | Enable `add_php_document=1`; retain explicit references to both Ajax-only Layouts so the compiler discovers them. Preserve subform/choices/fancy-select assets from the source View. Attach the UIkit/VDM uploader Library and files through native configuration; do not copy generated hashed asset registrations. |
| Shared helper | Use the enabled component admin/both helper area, directly or through reusable Custom Code, for the header, target and mapping methods. Keep `getLanguageTranslationsHeaders`, spreadsheet-header state and matching methods together. Custom Code follows its natural-key contract, not a made-up GUID for each PHP method. |
| Target schema and dependencies | Configure `Import.Entity` for the application's actual Admin View/table, key, match field and related writes. Pull the existing Powers below and their closure, and include the spreadsheet library/autoloader. The reference uses `language_translation`, numeric primary key `id` and match field `source`; those are domain choices, not defaults for every importer. |

The Custom Dynamic Get deliberately supplies session state, not an Admin View database row. Preserve the literal `$data =` assignment: the [Item-getter compiler](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Compiler/Dynamicget/GetItem.php#L450-L460) detects it and suppresses its database fetch. Returning the object directly is not equivalent. Generated `$db`/`$query` scaffolding does not mean this particular getter needs a queue table.

The [Customview loader](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Compiler/Customview/Data.php#L456-L499) resolves `main_get`, Libraries, presentation references and enabled hooks. The [custom-button loader](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Compiler/Model/Custombuttons.php#L127-L165) gates decoding of both `php_model` and `php_controller` on `add_custom_button`; merely filling those code boxes is insufficient. [Template/Layout resolution](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Compiler/Templatelayout/Data.php) follows aliases and nested references. Keep the source View's Layout-discovery comments until an equivalent explicit dependency path is verified.

The uploader's `entity` is the runtime operation GUID and `target` encodes the view name. Neither is an authoring-record identity. Apply reads `vdm_import`, recursively converts mapping arrays to objects, and resolves the file path from the owned session state rather than trusting a posted path.

## Follow the real caller and services

1. Read [Import_translationsController::importLanguageTranslations/cleanupImportState](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/admin/src/Controller/Import_translationsController.php). The Apply action checks CSRF and `import_translations.access`, resolves temporary file metadata from session state, sets entity parent table `language_translation`, parent key `id`, and matching link field `source`, then calls `execute(payload)->result()` synchronously.
2. Follow the actual upload and preview path through [AjaxModel](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/admin/src/Model/AjaxModel.php), `File.Agent`, and [ComponentbuilderHelper::getItemImportSubformValues/getLanguageTranslationsHeaders](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/admin/src/Helper/ComponentbuilderHelper.php). The controller's submitted file GUID check alone is not a general application upload-ownership implementation; bind the mapping/apply state to the uploader and exact session-owned file.
3. Read [Import Factory](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Import/Factory.php) and [Import service provider::getTransient](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Service/Import.php). The provider constructs Transient in this order: Message, Mapper, Data, Spreadsheet Reader, RowDataArray, Row, ParentTable, JoinTables, Assessor, Entity. Its factory registers Table, Database, Model, Data, Import, File, Spreadsheet and component-specific Import providers. A service name without this closure and its caller is insufficient.
4. Inspect [Mapper::set/getTableField](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Import/Mapper.php). Each mapping row has `column` and `target`; ordinary targets are `table.field`. Translation values use the two-value subform format `language_translation.translation|translation|language|<language-tag>`. The controller recursively converts posted mapping arrays to objects. Unknown targets can be skipped, and duplicate source-column keys can overwrite earlier mappings; validate required and ambiguous mappings in the caller before execution when data completeness matters.
5. Follow [Transient::execute/import/result](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Import/Item/Transient.php), [ParentTable::processParent](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Import/ParentTable.php), and [Import Item::get/processSubform2](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Import/Item.php). This is where mapping becomes actual model data and where matching existing `source` rows leads to update.

## Source-specific troubleshooting

These observations explain behavior in the inspected service implementations. Check the corresponding implementation on the target version when diagnosing a symptom; they do not require a replacement import framework for every application.

| Source behavior | Consequence for an agent |
| --- | --- |
| Transient catches row exceptions and continues | Returning normally does not mean every row succeeded or that earlier writes rolled back. |
| Only `null` from ParentTable counts as a failed row | Do not return `false`/`0` to signal validation failure in an adapter; use `null` or a caught exception consistently. |
| [Assessor](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Componentbuilder/Import/Assessor.php) uses an 80% success threshold | A success message can coexist with failed rows; it is not an all-or-nothing batch result. Zero processed rows is an error. |
| ParentTable ignores some Item setter booleans | If a reported row result disagrees with saved data, inspect the setter's return handling. A selected parent key does not independently prove a database write succeeded. |
| Import Item builds fresh subform values from mapped columns | A translation update is not source proof that unmapped existing languages are merged/preserved. Test on disposable rows before claiming preservation. |
| `execute()` removes `payload->maps`; `result()` clears Message state | Use a fresh payload per attempt and capture results once; reset/isolate other shared mutable services for independent runs. |
| [Header](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Spreadsheet/Header.php) reads the workbook's active sheet; [Reader](https://github.com/joomengine/Joomla-Component-Builder/blob/037752c7e6599aa4cec900138dfb61af7ee4ba8f/libraries/vendor_jcb/VDM.Joomla/src/Import/Spreadsheet/Reader.php) defaults to sheet 0 | Verify that preview, mapping and execution select the same sheet. |
| Exported `Source` header and helper matching rules differ | Inspect mapping after importing an exported example; do not assume automatic matching populated the source target. |
| Upload stores file metadata as an array, but the inspected `deleteTranslation()` reads `file_path` as an object property | Cancellation cleanup needs a runtime check and, if affected, a maintained-source correction; do not claim it works from source inspection alone. |
| Apply checks the submitted file value's GUID syntax but retrieves the path through session state | Verify exact operation/file ownership, including same-session and cross-session cases; a syntactically valid GUID is not an authorization check. |
| Controller cleanup clears upload-type/file entries but not the operation GUID key | Decide whether reuse is intended or a new operation must rotate the key, then test the complete lifecycle. |

If the feature promises preservation of unmapped languages, reproduce with two existing languages and an input mapping only one, then inspect the saved JSON. The inspected writer alone does not establish that guarantee.

Spreadsheet formats depend on the installed reader/library and its dependency closure. Test CSV and every advertised workbook format; literal cell values, formulas and calculated values have different contracts. Package the compatible reader library and autoloader in a generated consumer rather than assuming JCB's authoring host provides them.

## Acceptance and cleanup

In a disposable [Playground](../../testing/playground/README.md), create synthetic source strings with two languages. Use the actual **Download Example** action, fill in one existing source string and a changed translation, upload that file, inspect/correct all header targets and Apply. Compare saved values with the intended update and verify the returned result. A successful download and a separate manually constructed input do not exercise the shared header/mapping contract. Test missing source, unknown mapping, duplicate mapping, empty file, a row exception among valid rows, active sheet other than 0, a denied account and a repeated request. Compare row counts and JSON, and retain errors even when a success message is also present.

Verify file/session cleanup after success, rejection, cancellation and unexpected errors. The native controller explicitly clears session keys and deletes the recorded file through `File.Agent`; validate the caller's ownership and lifecycle before copying it into another component. A file path supplied directly by the request must not replace that session-owned reference. Report exact observed rows and remaining formats/permissions untested.

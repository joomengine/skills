# Service Directory J6: follow links through the frontend

This is a source trace for the [Site Router skill](../workflows/site-router.md), not a second router workflow. It uses [the J6 component's editable package records](https://github.com/joomengine/joomla-packages/tree/90145b345a7fc0a05b66cb7c979419971e47a27f/src/joomla_component/children/160d0efb-6bf0-48eb-8d46-55cf74729501) and [published frontend](https://github.com/joomengine/Joomla-Service-Directory/tree/d25ca95084d79e552e2ae99f67011679d41d3ad4/site). The exact menu prefix depends on the installed site. The route examples below describe the **component's** portion, not absolute URLs.

## Start with the visitor's action

| Frontend action | Where the link starts | What the fresh request must deliver |
| --- | --- | --- |
| Open the directory | Joomla menu item of the Directory type, generated from the `directory` Site View's Menu association. The JCB association also marks this view as the component default; the installed Display controller falls back to it. | `directory` and its category cards. A default Site View, an available menu type and an actual published Joomla menu item are three different things. |
| Open a category card | The Directory Dynamic Get's `php_after_getitems` builds a link from the category slug; the Directory view renders the resulting `item->link`. See [Directory Model](https://github.com/joomengine/Joomla-Service-Directory/blob/d25ca95084d79e552e2ae99f67011679d41d3ad4/site/src/Model/DirectoryModel.php#L204-L229). | `category` with the category's numeric `id`, not a company ID. The Category Dynamic Get applies the category filter to companies. |
| Search from the Directory or Companies page | The `getSearchLink` Custom Code block is called with `getCompaniesRoute`. It prepares the route base and current term for the shared `searchbox` Layout. Enter and the search button navigate to the base plus the encoded term. Clear returns to the base. | `companies` with the expected `search` value; no record ID is needed to identify this view. See [Directory display](https://github.com/joomengine/Joomla-Service-Directory/blob/d25ca95084d79e552e2ae99f67011679d41d3ad4/site/tmpl/directory/default.php#L47-L67) and [Search Box](https://github.com/joomengine/Joomla-Service-Directory/blob/d25ca95084d79e552e2ae99f67011679d41d3ad4/site/layouts/searchbox.php). |
| Open a tag, expertise area or language, then search within it | Models populate the category and related-entity links from each entity's own ID and alias. The company results and listing details render them through `companyrelationships` and its child layout. The facet Site View uses its own RouteHelper method for the Search Box base. | `category`, `tag`, `areaofexpertise` or `lang` with the facet's numeric `id`; when searching, keep that same ID and add `search`. Clearing drops only the term. The `lang` view is a **directory facet**, not Joomla's site-language context. |
| Open a company card | The model's `buildItemLink()` sends the company slug through `RouteHelper::getListingRoute()` and Joomla routing. The shared Companies template reads `item->link`, separate from `item->edit_link`. | `listing` with the company ID. The Listing model reads that ID and loads the published item; the Listing template composes company details, extras and relationship links. See [link preparation](https://github.com/joomengine/Joomla-Service-Directory/blob/d25ca95084d79e552e2ae99f67011679d41d3ad4/site/src/Model/CompaniesModel.php#L650-L715), [results template](https://github.com/joomengine/Joomla-Service-Directory/blob/d25ca95084d79e552e2ae99f67011679d41d3ad4/site/tmpl/companies/default_companies.php#L22-L65) and [Listing display](https://github.com/joomengine/Joomla-Service-Directory/blob/d25ca95084d79e552e2ae99f67011679d41d3ad4/site/tmpl/listing/default.php). |
| Add or edit a company; save or cancel | Directory has a create link to the `company` edit layout with a return context and gates its display. Results and listing detail use the model's permitted `edit_link`, which targets the `company.edit` task with a numeric ID. This comes from the Company **Admin View** with frontend create/edit enabled, not another public detail Site View. | Enter the authorized native form, post the appropriate controller task, then follow its internal return or fallback. Display/Company controllers check edit context and authorization; link visibility is not access control. Use the [native Site Edit View skill](../workflows/site-edit-view.md) for new builds rather than copying the Directory's direct create-layout link. See [Company controller](https://github.com/joomengine/Joomla-Service-Directory/blob/d25ca95084d79e552e2ae99f67011679d41d3ad4/site/src/Controller/CompanyController.php#L265-L381). |

Controller redirects, edit and modal forms, pagination, AJAX, and ticket tasks are distinct from the custom public route contract. The component includes native Company and Ticket form/task flows; do not add every frontend task to `build()` and `parse()` simply because it has a link. When changing the router, check that those flows still reach their own Joomla consumers.

- **Page composition:** In the editable package, Site View `php_view` (Custom View Script) calls [`getSearchLink`](https://github.com/joomengine/joomla-packages/blob/90145b345a7fc0a05b66cb7c979419971e47a27f/src/custom_code/getSearchLink/item.json) with one argument, the appropriate helper method. Its `default` field passes the prepared URL and term to the [Search Box Layout](https://github.com/joomengine/joomla-packages/blob/90145b345a7fc0a05b66cb7c979419971e47a27f/src/layout/f9d33ff5-1621-4f7b-b55e-191960389d94/item.json). In the published artifact inspected here, the expanded setup is visible above the markup in the generated templates. Preserve the editable separation: put initial PHP setup in Custom View Script without PHP tags and render in the template. Use compiler tracing on the installed version to locate output; don't copy generated placement back into JCB.
- **Filter and link preparation:** The Companies/Category Dynamic Gets' `php_getlistquery` uses `modelCompanySearchQuery`. Tag/Expertise/Language use `companiesDataSetter` to resolve the incoming numeric facet ID to the relationship GUID, filter the matching companies, and apply the search. The list getters use `companiesDataSetMapper` in `php_after_getitems`. Site View `php_model` brings in `processServiceDirectoryItem`: its model methods produce listing, edit, category and related-entity links. These are not Router methods. Keep the route-to-input mapping and result filtering in their respective layers.
- **Present the result:** The [Companies Template](https://github.com/joomengine/joomla-packages/blob/90145b345a7fc0a05b66cb7c979419971e47a27f/src/template/7e779cb8-0d76-4141-ba0d-1e3f80026260/item.json) is reused by the list/facet views, generating their `default_companies.php` partials. The Listing view uses its own templates and the [Company Relationships Layout](https://github.com/joomengine/joomla-packages/blob/90145b345a7fc0a05b66cb7c979419971e47a27f/src/layout/ca28683a-d899-4f33-a771-a7b3b95fe2d3/item.json). Keep one source for reusable link logic. Do not reconstruct paths independently in each card, Layout and JavaScript handler.
- **Keep identity layers separate:** The route's `23:acme` is a runtime record ID and slug, not a JCB blueprint GUID or the relationship GUID. Category and listing can both have ID 23 and resolve to different tables and views. The Component Router's build/parse helpers use category, tag, area-of-expertise, language and company tables respectively. The model still decides what the visitor may see.

## Walk one link in both directions

Suppose company ID `23` has alias `acme`. The model gives the RouteHelper the slug `23:acme`, which becomes the internal query `option=com_servicedirectory&view=listing&id=23:acme` plus any applicable return context. Joomla resolves the menu context and calls the component router. With IDs retained, the component's build method returns `['listing', '23:acme']`; with IDs removed it returns `['listing', 'acme']`. The paired parser reads the numeric prefix or looks up the alias in the company table, restoring `view=listing&id=23`. The Listing model then reads numeric `id` to load the row. The emitted segment array is not a promise about Joomla's rendered punctuation or menu prefix.

Search follows a parallel path: the installed Search Box appends a term to the base routed URL, and the Directory router parses it as the first segment after `companies`, or after the item segment for a facet. The target Dynamic Get applies the parsed term. Test the rendered link or browser action, the parsed inputs, and the resulting records. A correct-looking URL or a 200 response is insufficient.

**Adopt the architecture, not the incidental implementation.** The published Search Box assumes an appendable SEF path and filters input to a limited ASCII character set before encoding. That is not a general pattern for non-SEF URLs or multilingual search. For new builds, prefer passing the decoded search value as a regular named request parameter and letting Joomla build the URL. Only encode search as a path segment when the required behavior justifies a matching build/parse contract. Test both SEF settings and search/clear/pagination together. Use the [authored-code standard](../../standards/authored-code.md) for context-appropriate escaping; don't copy inline click handlers or raw interpolation from the specimen.

**Evidence:** editable records and published files were inspected. A direct PHP smoke test on the published Router passed all seven public build/parse cases in ID-retaining mode, including preserving the listing return query. It used a stand-in for the Joomla parent and did not exercise menus, database alias lookups, browser actions or a fresh Playground install. Use the [verification sequence](../workflows/site-router.md#3-compile-and-verify-in-playground) before signing off an implementation.

## UI observations and validation limits

A read-only Playground inspection on November 10 used **Joomla 6.2.0, JCB 6.2.0, PHP 8.4.27**. Language Translations had no records in that fresh deployment. Import help described export, translation columns, immediate upload, mapping and Import; it advertised CSV/XLSX/XLS/ODS/Gnumeric. The Languages list contained six published entries and a Build button. No export with actual rows, import or compile was performed in that inspection.

The UI help states that existing translations are not removed. The earlier inspected writer does not by itself establish preservation of unmapped languages; retain the workflow's explicit saved-value check instead of claiming an untested guarantee.

The workflow examples and expected generated key/INI pair are teaching examples supported by source, not a claim that each has run in Playground. Quote-sensitive extraction, comment-only import placement, each presentation consumer, combined-filter workbook scope, mapped update/preservation, recompilation and installed language switching require the [acceptance sequence](../workflows/language-strings.md#acceptance-and-troubleshooting). Record later actual results here without replacing failures or unrun stages with a generic “passed.”

Repository static checks and CI validate skills consistency only. Their actual commands/results belong in the PR and do not prove the component's multilingual runtime.

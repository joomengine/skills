## UI observations and validation limits

A read-only Playground inspection on November 10 used **Joomla 6.2.0, JCB 6.2.0, PHP 8.4.27**. Language Translations had no records in that fresh deployment. Import help described export, translation columns, immediate upload, mapping and Import; it advertised CSV/XLSX/XLS/ODS/Gnumeric. The Languages list contained six published entries and a Build button. No export with actual rows, import or compile was performed in that inspection.

The UI help states that existing translations are not removed. The earlier inspected writer does not by itself establish preservation of unmapped languages; retain the workflow's explicit saved-value check instead of claiming an untested guarantee.

The workflow examples and expected generated key/INI pair are teaching examples supported by source, not a claim that each has run in Playground. Quote-sensitive extraction, comment-only import placement, each presentation consumer, combined-filter workbook scope, mapped update/preservation, recompilation and installed language switching require the [acceptance sequence](../workflows/language-strings.md#acceptance-and-troubleshooting). Record later actual results here without replacing failures or unrun stages with a generic “passed.”

Repository static checks and CI validate skills consistency only. Their actual commands/results belong in the PR and do not prove the component's multilingual runtime.

## Bounded live compilation and export inspection

A later authorized exercise on the same Joomla/JCB/PHP target saved two literal probes in the Demo's Looks Site View and compiled Demo successfully. The retained installer SHA-256 is `72e653b41f13f40bc46650579e41c509decaf79bfda663e9f86226e63bed7617`.

- `site/tmpl/looks/default.php` contains `use Joomla\CMS\Language\Text;` and calls to `COM_DEMO_SKILLS_LANGUAGE_ROUND_TRIP` and `COM_DEMO_SKILLS_LANGUAGE_SECOND_MESSAGE`.
- `site/language/en-GB/en-GB.com_demo.ini` contains the exact source values `Skills language round trip` and `Skills language second message`.
- Language Translations contains the two collected source records. Their local IDs are not portable identities.
- With Demo selected and a search narrowing the visible list to those probes, the export's hidden data table populated with additional non-probe rows. Its headers were Source, `af-ZA`, `nl-NL`, `fr-FR`, `de-DE`, `pt-PT` and `ru-RU`. This directly confirms that search did not restrict export data on this target. No downloaded XLSX was obtained at this stage, so it is not evidence of a completed workbook round trip.

This establishes the bounded Site View source-to-generated-key/INI/translation-record path. An import already present in a compiler template does not prove insertion into an import-free file. Comment-only import placement, Template/Layout/Custom Code consumers, quote-sensitive extraction and installed language switching remain separate acceptance cases, not covered by the two plain-text probes.

The attempted browser Excel export populated its data table but did not produce a retrieved download during this exercise. A separately constructed synthetic workbook is not an exported artifact and cannot establish the export/import round trip. The separate synthetic-workbook exercise below establishes import and translated recompilation, but not recovery of the original export download or an installed language-switch test.

## Synthetic workbook import and translated recompilation

The separate XLSX contained the two exact collected Source values and an `af-ZA` column. Its SHA-256 is `7cdbaf5a72e3b9df0245de7e1e129afeb39a5ed0814bb7b9232b0bb7c4322490`. Upload opened the mapping form, automatic Source/Afrikaans mappings were inspected, and the immediate import reported two processed rows with 100% success. Both source rows subsequently showed an Afrikaans translation; reopening a row confirmed the saved value, rather than relying only on the import message.

Recompilation at the existing 30% threshold succeeded but reported Afrikaans exclusion: 2 of 196 source strings translated (approximately 1.02%). An isolated test temporarily lowered the threshold to 1%, then recompiled. The retained translated installer SHA-256 is `d0f09af370eeba64f998696417fd42bf96d5cf77b2ddfc724906c884fae7046d`. Its manifest references `language/af-ZA/af-ZA.com_demo.ini`, and `site/language/af-ZA/af-ZA.com_demo.ini` contains exactly:

```ini
COM_DEMO_SKILLS_LANGUAGE_ROUND_TRIP="Vaardighede se taalrondrit"
COM_DEMO_SKILLS_LANGUAGE_SECOND_MESSAGE="Vaardighede se tweede taalboodskap"
```

This proves the bounded **synthetic XLSX → inspected mapping → saved translations → threshold exclusion/inclusion → emitted translated INI and manifest** path. It does not prove actual exported-workbook recovery, update/preservation of a pre-existing different translation, every supported format/filter combination, clean installation or runtime language switching. The threshold adjustment was a disposable diagnostic, not a recommended production completeness policy.
